# Song-building tools: first release

The user explicitly authorized undo/redo, bulk editing, named sections and controlled variations in the existing GUI. This product instruction overrides the default GA-only scope. The branch incorporates main through 7a0385a (merged PR #47). Arrange Song remains the next release.

- Added bounded session undo/redo for notes, tempo, samples, envelopes, extensions and section/protection metadata. Painting and pointer-slider gestures are single entries; bulk operations are atomic. Undo restores shared decoded sample buffers synchronously, stops transport and cancels pending asynchronous loads. Both undo and redo retention enforce the 128 MiB additional sample-memory ceiling; at most 50 edits remain. Loading/importing/reloading and saving a recovery copy reset history. History itself is not serialized.
- Shared APIs drive phrase/bar/track copy, cut, paste, clear, repeat, nudge and synth transpose. Clipboard data is dimension/mono validated, bounds failures are atomic, transpose refuses octave overflow, and edits retain unselected data. Shift-selection keeps a fixed anchor and dialogs retain their range.
- Named nonoverlapping sections persist in IndexedDB and portable JSON. Duplication, move and resize keep notes and labels aligned, expanding capacity in 12-phrase increments without discarding content beyond 48. Extending repeats source material; shortening trims it. Timing reflects the existing playback rule that empty phrases are skipped.
- Deterministic Sparse, Driving, Syncopated and Answer transformations reuse existing pitches. Kick and lead are protected by default. Preview is separate from live song state, with full-mix original/variation audition using current samples, envelopes and effects. Apply recomputes from validated inputs; stale or modified preview payloads cannot smuggle changes to protected tracks. Close/discard/load cancels rendering and stops audition sound.
- Added 21 Chrome tests covering real pointer painting, sample drop and mixer/envelope restoration, all transformations, malformed input, section capacity/reordering, portable persistence, audition PCM/cancellation, held sample decodes, native text undo, session limits, two-tab conflicts and recovery-copy boundaries. Preview/full-render comparison uses identical frame counts and <1e-6 peak PCM difference (native compressor contexts can differ by a few float32 ULPs). A real 129 MiB sample buffer checks the redo-retention limit without decoding or persisting it. All 21 focused tests pass.
- Browser verification: LE FEU RESTE remained at 130 BPM. Created a temporary section and undid it; Driving preview reported 18 added notes with 909 Foundation and Voyetra Main Lead protected; played, stopped and discarded the preview. No browser error logs. Original notes/samples/section labels were preserved. Desktop and 390px screenshots were visually inspected; centered the native dialogs explicitly because the global CSS reset removed their default margins.

The compiler-owned full regression, static, contract, architecture, commit-range and audio-oracle results are authoritative in this task's manifest, logs and verdict. No contract, threshold or baseline was weakened. Samples, generated song audio and UI screenshot fixtures are excluded from the commit.

This preserves atomic synchronous restoration without duplicate resets and keeps the existing auditable reset path. The oracle, thresholds and governance rules are unchanged.
