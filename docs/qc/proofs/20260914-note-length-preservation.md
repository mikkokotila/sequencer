# Preserve note duration during tempo correction

The user explicitly requested completion of the LE FEU RESTE conversion, including the envelope limitation. That authorizes product work despite the default GA-only scope. Work began from current origin/main, 2d09ac9, on a clean branch.

- Added per-track `gateSteps` (1–64 sixteenth-note steps; default 1) to the envelope API and GUI. Existing API callers and older files retain their previous duration. MIDI still releases on note-off; samples with ADSR off are unchanged.
- Live audio, full-song rendering and tail allocation use the same release-offset calculation. Phrase bounces allocate enough tail for long final envelopes. The control persists in IndexedDB and portable JSON; invalid numeric values are rejected before changing the live song. Popup positioning keeps the control visible on narrow screens. Input commits immediately, including when the user closes the popup without tabbing away.
- Four new Chrome tests verify GUI export/import/reload/reset and mobile visibility; invalid API/file lengths and legacy defaults; bit-identical envelope PCM for all nine tracks after 65→130 BPM / 1→2-step conversion; MIDI hold behavior; captured export settings; live source start/stop timing; full-song waveform agreement; and audible final-note tails in loop/song buffers. A negative control at 130 BPM with the old one-step length produces a measurable mismatch. The initial live fixture needed the normal Play gesture to resume its audio context; the corrected fixture exercises the real scheduler.
- LE FEU RESTE retains 1,924 event onsets/pitches, all nine embedded source samples, 24 occupied phrases and capacity 36. The four enabled envelopes use two steps at 130 BPM. All remaining mix, effect and ADSR settings match the original 65 BPM song. Arrangement duration remains 177.230769 seconds; WAV/MP3 with tails last 177.648186 seconds.
- The full song was re-exported through the app API and compared with the original WAV and a fresh 65 BPM reference. Frame counts match. Complete mixes are not byte-identical; the measured residual against the original is -125.08 dBFS RMS, over 106 dB below the signal. Exact figures for both comparisons and sample hashes are committed in the proof directory. Individual envelope PCM is bit-identical in the focused tests.
- In the in-app browser, imported the completed conversion, reloaded, and verified two-step lengths for 909 Air, Mini Motor Bass, Omni Horizon and Voyetra Main Lead. The original 65 BPM song/file remains preserved. The earlier incomplete conversion is archived outside the repository. No sample assets or song audio are committed.

Authoritative full-suite, static, architecture, contract and audio-oracle results are generated by gov:commit's embedded governance check in proof.manifest.json and verdict.json. No gate, threshold, contract or baseline is weakened.

## CI observation correction

The first GitHub compiler run failed one dense-polyphony sync observation, although both local full runs and GitHub's separate E2E job passed. Its before/after clock window excluded the emitted step near a boundary. The runner did not retain the application's intermediate raw timestamp, so that particular native refresh cannot be established directly from the log.

Inspection found that the fixture read the native timestamp independently before, during and after the callback. A deterministic intermediate estimate refresh reproduces the same false stale-frame verdict with correct scheduling; the reproduction and CI failure are retained. The fixture now captures one native timestamp estimate per callback and shares it through the observer microtask. Performance time and the audio render head keep advancing. The observer applies the same validity rules for future/stale timestamps as the separately tested output-clock contract. A read-count assertion enforces one native snapshot.

The 1 ms visual tolerance, 30 ms maximum observation span, one-sample cross-track audio limit, CPU throttling and 180 ms stalls are unchanged. A negative control still rejects a frame one step behind. No production scheduler, output clock or DSP code is changed by this correction. The final compiler-owned full run and latest PR checks must pass before completion.
