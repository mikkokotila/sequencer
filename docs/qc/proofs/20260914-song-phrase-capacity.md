# Song phrase capacity and frozen note labels

- Explicit user instructions authorize product work despite the default GA-only scope. Started from latest main after PR #45 merged, with no pre-existing local product changes.
- Song capacity: choose 12, 24, 36, or 48 phrases; default 36. GUI shows twelve slots per row and reserves the actual pane height so the last track remains accessible. Both GUI and programmatic callers use setPhraseCount().
- Persistence: store the selected capacity per song and in JSON exports. Legacy songs gain 36 slots without changing their notes or BPM. Files with invalid counts or more data than the selected count are rejected before state mutation. A completed programmatic song load now refreshes the GUI too.
- Data protection: reducing capacity requires every removed phrase to be empty across drums, melody and sample tracks. An out-of-range empty editing phrase is rebound inside the retained range. Shrinking stops playback to clear any manually queued removed phrase; expansion leaves playback running.
- Frozen labels: only melody cells scroll horizontally; note labels remain outside that region. The scroll region supports keyboard focus and has an accessible track name.
- Chrome verification covers all three melody grids, 390px/600px scrolling, 1280px layout, label hit targets and last-step pitch mapping. Capacity coverage includes all four choices, twelve-slot rows, reload/new-song defaults, last-track accessibility, all-track shrink protection, legacy/JSON round trips and malformed files.
- Playback crosses phrases 12/13, 24/25, 36/37 and 48/wrap with exact scheduled step spacing. A full 48-phrase render at 130 BPM lasts 354.461538 seconds and retains the final hit. Loop export includes phrase-48.wav. Production GUI export/import and two-tab conflict recovery cover the saved count and late-phrase notes.
- The independent S2400 reader checks all 48 dense patterns and 15360 hits with deterministic bytes. Its per-event bit assertions use Node strict assertions to avoid tens of thousands of Playwright reporting steps; the same checks remain enforced. KIT/S24/MIDI map/sample completeness checks remain in the full suite. Physical hardware playback is unverified.
- Initial frozen-label test failure came from Playwright's minimal vertical scroll placing rows beneath the fixed phrase pane. Centering each grid before hit-target checks resolved the fixture error without changing the product fix.
- The first full run passed all 159 Chrome tests and all eight oracles, but failed the specification binding because persistence_roundtrip was omitted from the declared oracle list. Added the declaration and reran the required compiler check; no product-code change was needed.
- The second full run again passed 159 browser tests, but the benchmark oracle rejected one clock-boundary contradiction (upper bound 1.081 ms versus a 2 ms wall-clock lower bound). The wall endpoint was sampled after the acknowledged endpoint; a scheduling pause in between can create that contradiction. A deterministic six-millisecond post-acknowledgement pause reproduced the old failure. Capture the wall endpoint before requesting acknowledgement so both bounds cover the same DSP span. The 0.2 ms precision allowance, independent evidence validator, p99 budget and real-overload failure checks are unchanged. An excerpt of the original failed measurement is retained in clock-boundary-failure.json.
- Full checks and compiler-owned audio oracles run through gov:commit's embedded check; authoritative results are recorded in proof.manifest.json and verdict.json.
- LE FEU RESTE remains at its stored 65 BPM. It was composed with a 130 BPM pulse to fit the former twelve-phrase limit. Capacity expansion preserves existing music; retiming that composition is separate from changing the package's capacity and requires preserving onset and envelope timing.
