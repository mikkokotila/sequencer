## Observations (not fixed — recorded for follow-up)

### O-1 — Two AudioContexts; the uniqueness test cannot see the first

Instrumenting via `page.addInitScript` (before any page script) shows
`ctxCount: 2, states: ['suspended', 'running']`. The existing test
`AudioContexts are unique — Tone is bound to the engine context` patches
`window.AudioContext` *after* `page.goto`, so it structurally cannot observe a
context constructed during module init — it asserts uniqueness over a set it
started counting too late. The live context is correct and Tone is bound to it,
so no runtime timing bug follows; the cost is a wasted suspended context and a
test that provides weaker assurance than it appears to. Fixing belongs in a
task that can take the `audio:gates` obligation set.

### O-2 — Unreachable branch in `advancePhrase()`

`findNextPhrase()` wraps and returns `fromIdx` when all other phrases are empty;
it never returns a negative index. The `if (next < 0) stopPlayback()` branch is
therefore dead against current wiring. Retained deliberately as a defensive
guard on the injected `TransportSource` interface. Noted because
`architecture-invariants.md` invariant 3 disallows dead contracts, and a future
audit may want to decide this one explicitly.

A hypothesis that this branch caused final-step audio truncation was tested and
**disproved** (`killedBeforeSounding = 0`); the song loops and never auto-ends.
